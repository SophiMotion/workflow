# 数字风洞 CFD 教学 Web 设计

- 日期：2026-08-18
- 状态：已批准（2026-08-18）
- 项目目录：`workflow/sophicar/cfd`

## 1. 项目摘要

构建一个无需真实硬件即可运行的数字风洞教学 Web。用户通过教程逐步调节虚拟风扇、观察 RPM、真实风速、车底压力和垂直载荷，并在 Three.js 三维风洞中查看流线、速度场和压力伪彩色。

首版使用浏览器端二维 D2Q9 LBM（格子玻尔兹曼方法）作为教学求解器，并明确标注其结果属于二维、低分辨率教学近似，不作为车辆工程设计结论。三维场景用于呈现二维求解结果和虚拟传感器数据，而不是宣称执行了完整三维 CFD。

## 2. 目标与非目标

### 2.1 首版目标

1. 在现代桌面浏览器中直接运行，不要求后端、Arduino、ESP32 或本地服务。
2. 用完整的实验流程解释风扇功率、RPM、真实风速、压力和载荷之间的关系。
3. 提供可操作的二维 CFD 教学场和 Three.js 三维数字风洞。
4. 支持基线实验、三档风速扫描、结果对比和 CSV 导出。
5. 将模拟数据、CFD 数据和 UI 状态拆成清晰接口，为后续真实硬件和 OpenFOAM 模式留出替换点。

### 2.2 首版非目标

1. 不连接真实串口、WebSocket、Arduino 或 ESP32。
2. 不运行服务端 OpenFOAM、SU2 或工程级网格计算。
3. 不承诺可信的 Cd、Cl、y+、边界层或湍流工程结果。
4. 不支持上传任意 STL/GLB 并自动生成 CFD 网格。
5. 不复制或分发 MakerWorld 模型文件；只借鉴模块化风洞的结构语言，使用原创程序化几何。
6. 不实现账户、云同步、数据库或多人协作。

## 3. 目标用户与学习结果

目标用户为中学到大学低年级 STEM 学习者、教师和桌面风洞制作者。

完成教程后，用户应能够：

1. 识别整流段、收缩段、测试段、模型台和风扇段的作用。
2. 区分风扇 RPM 与测试段真实风速。
3. 区分局部压力与结构载荷。
4. 理解动压随风速平方变化的基本关系。
5. 识别速度场、压力场、涡量和流线的不同含义。
6. 说明二维教学 CFD 与工程级三维 CFD 的边界。
7. 使用重复工况和对比图形成一份基础实验结论。

## 4. 产品路线选择

首版采用以下组合：

- React + TypeScript 负责教程、控制、图表和实验状态。
- Three.js / React Three Fiber 负责原创模块化风洞、车辆和流线渲染。
- Web Worker 运行二维 D2Q9 LBM，避免阻塞主线程。
- 浏览器内确定性模拟引擎生成虚拟 RPM、风速、压力和载荷。
- 统一 `TelemetrySource` 接口隔离数据来源，首版只有 `SimulationSource`。

未采用纯粒子动画作为唯一方案，因为它无法展示离散流场计算；未采用 OpenFOAM 作为首版方案，因为它要求后端计算、网格流水线和更复杂的验证流程。

## 5. 信息架构与页面布局

应用为单页实验台，避免多页面跳转打断教学流程。

### 5.1 桌面布局

- 顶栏：产品名、教学模式/自由实验模式、实验状态、全局重置。
- 左栏：教程章节、当前目标、操作提示和知识卡片。
- 中央：Three.js 数字风洞，占据最大视觉面积。
- 右栏：风扇控制、工况参数、场变量选择和当前读数。
- 底部抽屉：RPM、风速、压力、载荷时间序列与实验对比。

### 5.2 窄屏布局

- 中央三维画布保持在顶部。
- 教程、控制和图表改为分段标签页。
- 不把窄屏作为高性能 CFD 的主要目标；自动降低粒子数与 LBM 分辨率。

### 5.3 视觉语言

- 深色实验室仪表盘作为背景。
- 风洞主体使用米白、深灰和功能红，呼应参考图中的模块化结构。
- 青绿色表示流线和正常数据；黄色表示教学提示；红色只用于停止、超限和错误。
- 数字采用等宽字体，正文采用清晰的无衬线字体。
- 所有颜色编码同时提供文字、单位或图标，不以颜色作为唯一信息来源。

## 6. 教程章节

### 第 1 章：认识风洞

- 目标：识别五个主要模块。
- 交互：点击三维风洞热点，触发剖切、高亮和说明。
- 完成条件：依次查看整流段、收缩段、测试段、模型台和风扇段。

### 第 2 章：启动虚拟风扇

- 目标：观察目标功率与实际 RPM 的动态差异。
- 交互：解锁控制、设置 30% 功率、启动并等待稳定。
- 完成条件：RPM 连续 2 秒处于目标值 ±3% 范围。

### 第 3 章：读取传感器

- 目标：区分 RPM、风速、压力和载荷。
- 交互：悬停指标卡查看定义、单位、采样频率和模拟方式。
- 完成条件：完成四项指标说明，并在曲线上定位一次稳定段。

### 第 4 章：观察 CFD 场

- 目标：理解速度、压力、涡量与流线。
- 交互：依次切换四种场变量，暂停动画并检查固定纵向中心截面的尾迹。
- 完成条件：查看全部场变量，并回答内置的单句判断题。

### 第 5 章：风速扫描

- 目标：建立速度与动压/载荷关系。
- 交互：自动执行 30%、60%、90% 三个工况；每档包含爬升、稳定和采样阶段。
- 完成条件：三个工况均获得有效稳定窗口。

### 第 6 章：比较与解释

- 目标：理解 CFD 预测与虚拟传感器之间的偏差。
- 交互：叠加曲线、查看残差和教学解释。
- 完成条件：选出偏差最大的工况并记录原因。

### 第 7 章：形成报告

- 目标：完成可复现的实验记录。
- 交互：填写一句结论，打开可打印报告视图并导出 CSV。
- 完成条件：实验元数据、三个工况和结论均存在。

教程允许随时切换到自由实验模式；教程进度保留，控制限制解除。

## 7. 核心组件

### 7.1 `AppShell`

负责页面布局、模式切换、全局错误和响应式面板，不包含仿真逻辑。

### 7.2 `TutorialController`

用显式状态机管理章节、步骤、完成条件和提示。教程只能通过可验证的用户行为推进，不通过固定计时器自动跳步。

### 7.3 `ExperimentController`

管理实验主生命周期：`idle → ramping → stabilizing → sampling → completed`。任一运行阶段可以进入 `paused`，恢复后返回暂停前阶段；停止和重置均回到 `idle`。

### 7.4 `SimulationSource`

以固定时间步生成确定性的虚拟遥测。它实现未来硬件也必须实现的 `TelemetrySource` 接口，因此 UI 不直接依赖模拟公式。

### 7.5 `LbmWorkerClient`

向 Web Worker 发送入口速度、障碍物配置和质量档位，接收降采样后的速度、密度与涡量场。负责超时、重启和缓冲区生命周期。

### 7.6 `WindTunnelScene`

渲染程序化风洞、透明测试舱、车辆、截面、粒子和热点。场变量只通过稳定的数据纹理/缓冲接口输入，不读取教程内部状态。

### 7.7 `TelemetryPanel` 与 `HistoryChart`

展示当前值、单位、状态、稳定性和最近 60 秒曲线。图表最多保留 1,200 个 20 Hz 样本，避免无限增长。

### 7.8 `ExperimentReport`

汇总配置、稳定窗口统计、曲线摘要、教学免责声明和用户结论，负责可打印报告视图与 CSV 导出。

## 8. 模拟数据模型

首版默认以 20 Hz 更新遥测，使用固定种子的伪随机噪声，确保同一实验配置可复现。

核心字段：

```ts
type TelemetryFrame = {
  sequence: number;
  simulationTimeMs: number;
  phase: "idle" | "ramping" | "stabilizing" | "sampling" | "paused" | "completed";
  fanPowerPct: number;
  rpm: number;
  windSpeedMps: number;
  underbodyPressurePa: number;
  verticalLoadN: number;
  quality: "transient" | "stable" | "invalid";
};
```

计算规则：

1. RPM 使用一阶惯性响应逼近目标转速，停止时采用更快的安全衰减。
2. 风速由 RPM、风洞效率和第二个惯性环节得到，不能直接等同于 RPM。
3. 动压采用 `q = 0.5 × ρ × v²`，空气密度首版固定为 `1.225 kg/m³`。
4. 车底压力由动压和教学用压力系数得到。
5. 垂直载荷由动压、参考面积和教学用升力系数得到。
6. 噪声、零点漂移和采样延迟均为有界确定性模拟，并在教程中解释。
7. 所有输出明确显示“SIMULATED / 模拟数据”。

## 9. 二维 LBM 教学求解器

### 9.1 数值范围

- 模型：D2Q9、BGK 单松弛时间碰撞。
- 网格：默认 240 × 96；低性能档 160 × 64；高质量档 320 × 128。
- 边界：左侧速度入口、右侧开放出口、上下无滑移壁面、车辆截面 bounce-back 障碍物。
- 输出：速度大小、密度变化、近似压力、涡量和粒子采样速度。
- 运行位置：专用 Web Worker。

### 9.2 实际单位映射

真实风速先映射到稳定的 lattice velocity 区间，再进入求解器。映射只用于保持交互趋势一致，不用于声称真实雷诺数相似。UI 同时显示现实单位和“教学求解器归一化参数”。

### 9.3 三维结合方式

二维求解场代表车辆纵向中心截面。Three.js 将该场用于：

- 更新截面速度/压力纹理；
- 驱动测试舱内的实例化粒子；
- 估算车身表面的教学伪彩色；
- 显示尾迹和分离区的视觉提示。

三维场景不得显示“3D CFD 已完成”等误导性文字。

## 10. 数据流

```text
用户控制
  → ExperimentController
  → SimulationSource
  → TelemetryFrame
  → Zustand store
  → 指标卡 / 图表 / 报告

windSpeedMps + obstacle config
  → LbmWorkerClient
  → LBM Web Worker
  → FlowFieldFrame
  → Three.js 截面 / 粒子 / 伪彩色
```

控制状态更新和高频渲染状态分开：React 只订阅需要重渲染的低频派生值；粒子位置和动画时间保存在 Three.js/引用对象中，避免每帧触发 React 渲染。

## 11. 错误与降级

1. WebGL 初始化失败：显示静态二维风洞示意和完整教程文本，禁用三维步骤并解释原因。
2. LBM Worker 崩溃或超时：冻结最后有效场，遥测模拟继续，提供“重新启动求解器”按钮。
3. 性能低于目标：依次降低粒子数、LBM 网格和图表刷新率，并显示当前质量档。
4. 浏览器页面隐藏：暂停渲染和求解，保留实验状态；恢复后不补算隐藏期间的数据。
5. 数值不稳定：丢弃无效场、降低 lattice velocity 并重启当前工况；将事件写入实验日志。
6. 导出失败：保留内存中的实验数据并提供重试，不清空当前实验。
7. 用户启用减少动态效果：关闭粒子动画，保留静态流线和场切片。

## 12. 测试设计

### 12.1 单元测试

- RPM 与风速的一阶响应。
- 动压、压力和载荷公式及单位。
- 固定种子下的模拟可复现性。
- 实验状态机合法与非法转换。
- 稳定窗口判定。
- CSV 序列化。
- LBM 的静止场、入口流、障碍物反弹和有限步质量守恒容差。

### 12.2 组件测试

- 教程完成条件不会被单纯等待绕过。
- 控制范围、单位和模拟标签始终可见。
- 暂停、停止和重置更新正确状态。
- LBM 失败时出现降级界面并可重启。

### 12.3 端到端测试

- 从第 1 章完成一次三档扫描并进入报告。
- 自由实验模式下启动、暂停、修改功率和重置。
- 切换速度、压力、涡量和流线。
- 导出 CSV 并检查列名、工况与样本数量。
- 桌面与窄屏核心流程均无横向溢出。

### 12.4 视觉与性能验证

- 检查 1440 × 900、1024 × 768 和 390 × 844 三种视口。
- 检查 WebGL 上下文丢失恢复、减少动态效果和键盘导航。
- 中档设备以默认质量档达到流畅交互；性能门槛以运行时自适应为准，不硬编码单一 FPS 承诺。

## 13. 首版验收标准

1. 用户可在无网络后端和无硬件条件下完成七章教程。
2. 三维场景包含原创模块化风洞、透明测试舱、车辆和实时流线。
3. 风扇功率变化会产生连贯的 RPM、风速、压力和载荷响应。
4. 二维 LBM 在 Worker 中运行，UI 在计算时仍可交互。
5. 用户可查看四种场变量并完成三档风速扫描。
6. 所有数值均带单位、状态和“模拟/教学近似”标识。
7. 可导出包含实验元数据和遥测样本的 CSV。
8. 核心单元、组件和端到端测试通过，生产构建成功且控制台无未处理错误。

## 14. 后续扩展接口

首版不实现以下功能，但接口应允许后续替换：

- `Esp32TelemetrySource`：通过 WebSocket 接入真实设备。
- `WebSerialTelemetrySource`：桌面实验调试模式。
- `OpenFoamJobClient`：提交服务端工程 CFD 作业并获取结果。
- `ModelImportPipeline`：导入 STL/GLB，分别服务于三维展示和网格生成。
- `CalibrationProfile`：保存风速、压力和载荷的真实标定参数。

扩展功能不得复用“教学近似”标签包装工程结果；每种数据必须携带来源、求解器、版本和可信度元数据。
