# 浙大交通场景课程项目表达与 World Labs 深入开发方案

核查日期：2026-10-01。对象为 `../school/zju2026.html` 及同目录课程素材；参考 Sophicar 官网和 World Labs 官方文档。现有课程页正文为通用高校沟通提案，不据文件名推定学校已正式立项或完成教学。

## 1. 核心判断

适合把 World Labs 引入项目表达，优先价值是让环境、车辆和任务在同一空间里被理解。现有提案已把课程主张、三条选题、15 次课、参数化设计、缩比制作、关键功能和两轮验证讲清；薄弱点在于观众无法进入场景、理解具体冲突，或追溯某个设计结论的证据。

推荐主张：**以未来校园为共同试验场，让参数化移动体进入可体验的空间，并用可复现任务和测试证据解释设计选择。**

这不是以世界生成替换课程，而是补足表达与项目沉淀。课程继续以学生的问题定义、制造、交互和验证为主；助教维护共享场景底座，每组只做一个主要任务和 1–2 项真实能力。

### 现有表达的具体评价

| 维度 | 现有内容 | 评价 | 应补内容 |
|---|---|---|---|
| 用户与任务 | 一种人群、一条路线、一项任务；人/物/服务三类入口 | 可直接保留 | 真实观察、访谈片段、具体痛点与可检查的目标 |
| 课程节奏 | 15 次课；前期交互、中期装配、两轮迭代 | 组织完整 | 让某个项目沿时间线展示如何改变，而非仅看课程表 |
| 场景可读性 | AI 校园沙盘与前端状态动画 | 有整体气氛，缺少参与感 | 全局路线、行人/操作者视点、停靠/交接局部 |
| 参数设计 | 至少三种方案比较、CAD、制造文件 | 有工程入口 | 同场景 A/B 比较；车宽、转弯空间、舱门方向要可解释 |
| 功能与验证 | 计划中 1–2 项能力、异常反馈、测试与失败记录 | 边界诚实，尚非实测证据 | 运行条件、版本、原始日志、视频及结论限制 |
| 长期积累 | 成果归档与 Sophicar 工具 | 需要共同数据结构 | 项目→场景→车辆→任务→运行→证据的关联与版本 |

不做貌似客观的总分，因为没有学生作品、用户研究和运行记录可核验。当前评估针对提案表达，不评价实际教学成效。

## 2. 推荐的展示叙事

先做“实验材料从教学楼运到实验室”。不要一开始展示一整座无限校园。

1. **为什么发生：** 谁搬、搬什么、原流程在哪里造成困难。展示一条观察和设计目标。
2. **在哪里发生：** 一个教学楼装载点、一条低速道路、一个人车交互点和实验室交接区。
3. **怎样发生：** 装载→运输→让行→停靠→交接。用车辆与界面状态解释设计。
4. **为何选这个方案：** 同一环境比较舱体/车宽/开门方向，避免只比较渲染风格。
5. **凭什么判断有效：** 独立展示原型、仿真与实测记录，两轮迭代前后条件一致。

可以用 2–3 分钟完成一次讲解，这是展演建议，不是原课程硬性要求。2035 为设计情境；现实观察、未来假设、生成内容和验证结论分别标注。

### 三种证据级别

- `concept`：设计想象、AI 图、脚本动画；能说明意图，不能证明性能。
- `simulated`：由已记录版本、场景、种子与条件的引擎计算；仅在模型假设内成立。
- `measured`：实物或用户测试，包含过程记录、仪器/采样与适用范围。

生成一个好看的 3D 世界并不会自动把项目从 concept 升级为 simulated。

## 3. World Labs 的具体位置

### Marble：先让团队低门槛做空间试验

支持文本、单图、多图、全景、视频和 Chisel 三维布局；编辑、扩展、组合、录制与导出可用于空间方案迭代。产品 UI 的功能不能直接推定为 API 里全部有对应端点。[Marble 文档](https://docs.worldlabs.ai/)

当前已有沙盘图是模型式、俯视构图，直接生成更可能得到“可以围观的模型”。若要人在校园里体验，应先准备人眼高度的连续场景素材或布局。图片宽高 2:1 不等于等距柱状 360° 全景，不能把此沙盘图当作 pano 提交。

### World API：进入自己的作业流程

当前文档列出 `marble-1.0-draft`、`marble-1.0`、`marble-1.1`、`marble-1.1-plus`。请求必须显式锁定 model，避免默认值变化。`POST /marble/v1/worlds:generate` 返回 operation；保存 operation_id 后轮询，成功后取完整 World。身份头为 `WLT-Api-Key`，只放在服务端。[模型](https://docs.worldlabs.ai/api/models)、[生成接口](https://docs.worldlabs.ai/api/reference/worlds/generate)、[查询世界](https://docs.worldlabs.ai/api/reference/worlds/get)

需要处理 401/402/429、生成失败与等待超时。提交超时不能盲目重试 POST，否则可能重复生成和扣费；先在控制台排查并找回 operation。确认失败后才建立新作业。

### Spark：把 3D 空间放进自己的产品

World Labs 的 Spark 是与 Three.js 配合的 Gaussian splat 渲染器，可与独立 mesh 同场景显示。它适合作为 Sophi Worlds 的空间展示层，不是路网或车辆物理引擎。本页锁定官方入门示例列出的 Three.js 0.180.0 与 Spark 2.3.0。[Spark 入门](https://sparkjs.dev/docs/)、[SplatMesh](https://sparkjs.dev/docs/splat-mesh/)

浏览器试验可把 Spark、Three.js 与 Rapier 组合成物体碰撞和人物交互；官方交互示例提供了参考，但仍需做产品化封装与任务标定。[官方交互示例](https://docs.worldlabs.ai/api/interactive-world-examples)

### Atlas：关注，不做本轮交付依赖

官网已经介绍 Atlas，但本次查到的公共 API 模型列表仍是 Marble 系列。不要把研究展示或候补申请中的能力写进当前项目承诺。[Atlas 官方介绍](https://www.worldlabs.ai/blog/atlas)

## 4. 深入开发的分层架构

```text
Sophicar                           SophiStudio
车辆参数、CAD、制造版本             项目、团队、研究与过程文档
       └────────── 项目资产清单 ───────────┘
                         │
       ┌─────────────────┼──────────────────┐
       │                 │                  │
World API adapter   资产存储/版本服务     仿真任务服务
异步生成、额度控制    SPZ/GLB/JSON/视频    SUMO/CARLA/Isaac 等
       │                 │                  │
       └──── Sophi Worlds 浏览器工作台 ───────┘
          空间体验 / 车辆比较 / 任务回放 / 证据
```

未来入口可以分别使用两个站点上的项目链接；本轮不更改线上网站，也没有同步未提供的历史案例。

### 四个必须分开的层

| 层 | 内容 | 负责系统 |
|---|---|---|
| 外观层 | 建筑、植物、空间氛围、背景 splats | Marble + Spark |
| 工程几何层 | 车辆网格、标定道路、碰撞面、可行驶区 | CAD/DCC/人工清理 |
| 行为层 | 任务状态机、交通流、控制器、行人、故障注入 | 应用服务与仿真引擎 |
| 证据层 | 参数、版本、日志、指标定义、视频和结论 | SophiStudio 项目与实验库 |

静态场景尽量不生成车辆和行人，否则与后来插入的可控车辆重叠，而且难以独立编辑。用独立车辆 GLB、行人 actor 与语义标注获得可控性。

### 仿真方向如何选

- **课程交互 / 方案体验：** 先使用 Three.js 任务状态机，必要时用 Rapier 做简单碰撞；将结果标为交互演示，避免宣称车辆性能。
- **校园交通组织：** 可以评估 SUMO 的流量/路权模型；道路需建模，结果通过轨迹回放到展示层。[SUMO 路网](https://sumo.dlr.de/docs/Networks/SUMO_Road_Networks.html)
- **自动驾驶场景：** 可以评估 CARLA，但必须构建其可用地图与路网、可控参与者、传感器和场景脚本；导入一个 splat 并不会获得这些能力。[CARLA 自定义地图](https://carla.readthedocs.io/en/latest/maps_tutorials/)
- **机器人任务与传感：** 可评估 Isaac Sim；NVIDIA 已展示 Marble 环境进入机器人仿真工作流，但碰撞、材质、尺度、机器人与相机需要正确配置。[NVIDIA 官方集成参考](https://developer.nvidia.com/blog/simulate-robotic-environments-faster-with-nvidia-isaac-sim-and-world-labs-marble/)

以上引擎分工是架构建议，不是已经实现的集成。先选择一个主要验证问题，再选择引擎；不要同时维护三套后端。

## 5. 几何与数据合同

### 坐标、尺度和资产

API 的 `assets.splats.semantics_metadata` 提供 `metric_scale_factor` 与 `ground_plane_offset`。按照官方规则，先把原始 Gaussian 中心和尺度乘以 scale，再对中心的 y 减去 offset，最后进行渲染器轴转换。Three.js 显示 Marble 原始资产时，再绕 X 轴旋转 π。不要复用文档里的示例数字。[尺度与坐标规则](https://docs.worldlabs.ai/api/rendering-spz)

本页实现为内层 SplatMesh 的统一 scale 和 y 偏移，再由父 Group 执行轴转换。没有 metadata 时仅用 1/0 查看，不视为已标定。不要对已经变换到工程坐标的资产重复变换。

正式项目采用明确的米制右手坐标，保存 `T_world_asset` 4×4 变换和车辆局部坐标约定。实测关键距离并记录误差；碰撞 GLB、CAD 车辆与 splat 的坐标需分别确认。课堂缩比物理模型 1:10 / 1:5 的映射是独立变换，不能混入全尺寸数字场景。

SPZ 用于外观；碰撞 GLB 是粗代理。高质量 GLB 也不自动满足 CAD、路网或可靠碰撞要求。[导出规格](https://docs.worldlabs.ai/marble/export/specs)、[Mesh 导出](https://docs.worldlabs.ai/marble/export/mesh)

### 推荐归档实体

| 实体 | 必需字段 |
|---|---|
| Project | project_id、来源、标题、负责人、核心任务、访问权限、成果授权 |
| WorldVersion | world_id、provider、model、输入摘要、资产哈希、尺度、坐标、生成费用 |
| VehicleVersion | vehicle_id、CAD/GLB 版本、尺寸单位、参数快照、碰撞代理 |
| ScenarioVersion | 路线、参与者、事件条件、天气、seed、成功/失败规则 |
| Run | run_id、引擎与版本、world/vehicle/scenario 引用、开始结束时间、配置哈希 |
| Evidence | 来源类型、原始日志/视频、指标定义、结果、限制、复核者 |

本轮 `data/project-template.json` 只实现面向展示的最小项目清单；正式 schema 后续扩展，不能声称已经拥有团队权限、后端同步和完整实验管理。

### 性能与版本

先尝试 100k/500k 资产；手机优先低清与静态图降级。大场景分区、LOD 和缓存属于下一阶段。在目标设备测首帧时间、下载量、帧率和内存，再决定资产预算；不要提前承诺全机型流畅。

资产应自有对象存储并保留哈希与来源，避免临时签名 URL 失效。生产时锁定并本地打包依赖，限制 CORS 与访问范围，保留删除/撤回项目资源的能力。前端不保存密钥。

## 6. 从零开始的最小试验

### 试验 A：桌面沙盘表达

以 `assets/campus-concept.png` 为参考，试做与现有课程语言一致的模型式世界；观察从平面图到可浏览空间是否增加理解。已有图片含车辆，适用于表达试验，不建议直接作后续动态仿真底座。

### 试验 B：全尺寸交接区

使用 `prompts/campus-transfer.txt` 从文本开始，或另备同一交接区的眼平图、全景、Chisel 粗布局。保留空路面，动态车辆后加。把失败样本也保存下来。

### 试验 C：同一场景的两种车辆方案

固定世界与镜头；分别插入两种 CAD 参数方案。让评审解释哪一种更适合装卸与停靠。验证目标是表达质量；正式通行性仍以工程几何为依据。

### 建议验收门槛（需团队落实）

- 世界中能辨认起点、终点和路线，无明显阻断或多余静态车辆；至少检查俯视、操作者、交接点三个视角。
- 项目命名、来源、AI 标识、输入、模型与版本能够追溯。
- 同一任务至少跑通正常与一个异常路径；异常状态不能被动画直接跳过。
- 页面能区分生成外观、任务示意、仿真结果和实测结果。
- 至少一次用户讲解测试：观众能说出用户、任务、关键决策和证据范围。记录实际反馈，不预设成功。

## 7. 预算与实施顺序

以下为 2026-10-01 官方 API 费率下的算术估计：文本草稿 230 credits，文本标准生成 1,580 credits；1,250 credits = US$1。6 草稿 + 2 标准 = 4,540 credits = US$3.632。一次 HQ mesh 导出另需 3,500 credits = US$2.80。API 最低充值 US$5；Marble 网页订阅与 API 额度不互通。实际支付、税费、失败处理和后续费率以平台为准。[API 计费](https://docs.worldlabs.ai/api/pricing)

Marble 网页套餐的下载、导出和商业使用权限各有条件，选择前在官方套餐页确认用途。[Marble 方案](https://marble.worldlabs.ai/pricing)

不要一次为全班生成所有世界。建议先由助教完成小样，记录每轮输入、人工修复时长、可用率与资产体积。余额不是硬预算开关；服务端应限制新增作业次数、单项目额度和并发，不自动重复提交超时作业。

建议节奏而非承诺工期：

1. **空间小样：** 一个节点、少量草稿、两种输入方式；确认有表达增益才继续。
2. **网站接入：** 一个已生成世界、一辆独立车辆、一个可解释任务；形成可分享页面。
3. **单引擎验证：** 选一个主要研究问题；统一坐标、碰撞与运行合同，能复跑一次异常实验。
4. **案例平台：** 在验证过的最小链路上增加账号、对象存储、权限、生成队列和项目同步。

## 8. 本次交付与边界

`worldlabstestv1.html` 是可运行的本地概念工作台，包含三类任务、阻挡/解除、进度拖动、场景热点、表达评估、开发路线、项目搜索筛选、新增、JSON 导入导出，以及真实空间资产接入入口。任务动画只说明逻辑，不输出仿真性能指标。

所有预置案例均为课程提案或未来入口，未同步线上项目。当前没有实际 World Labs 账号或课程世界；未调用付费生成、未发布外网、未进行硬件或仿真联调。浏览器元信息不是多人数据库；本地文件不随 JSON 自动复制或上传。

`tools/worldlabs_client.py` 为只依赖 Python 标准库的 API 起步工具：默认 dry-run；显式提交后保存 operation，支持查询与导出项目清单。真实 API 行为仍需账号与额度验证。
