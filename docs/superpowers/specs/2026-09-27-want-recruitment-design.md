# Want 招聘工作台设计

日期：2026-09-27  
状态：整体方案已获确认；本书面设计供用户审阅，尚未进入实现。  
项目：`/Users/wubo/Documents/2026-2/sophistudio`

## 1. 目标与已确认范围

将现有四岗招聘接入 SophiStudio 工作流，在根目录提供 `want.html`。用户可以查看所有历史已读资料的分类与依据，重新阅读并追加复核，清楚识别实际发送的消息，按筛选结果导出。后台负责批量模型评估与持久任务管理，减少逐条模型调用和每次发送后的全量导出。

当前岗位为电控、机器人导航、车辆结构、后端开发。3D 打印已归档，保留其全部资料和沟通历史。现有每岗每天阅读 100 位不同候选人、向合适且完成完整简历核查的 20 位候选人发起沟通的目标继续适用；不因人数不足降低匹配要求，不因两个时段而翻倍。四条已确认话术继续有效，新撰写的二次回复保存为草稿。

新增要求：全部已读资料都可分类表述；支持二次阅读；实际发送的消息正文在网页和支持格式的导出中高亮。

## 2. 现状与性能依据

已有 1034 条阅读记录，包含 885 条摘要级记录、149 条详细级记录；这些是记录数，不等同于不同候选人数。原始身份键并非全部为平台唯一 ID，不能按姓名直接合并。现有 JSON 约 1.54 MB，读取解析平均约 8.31 毫秒。完整 Excel/HTML 同步在临时副本测得一次 20.11 秒。当前全量导出与浏览器交互是优先优化对象，尚无完整分阶段耗时数据。

现有 `recruitment-data.json`、`recruitment-config.json` 和 Excel 保留为兼容基础。SophiStudio 的 DSH AI 网关目前为演示实现，不作为真实模型调用或发送成功依据。

## 3. 用户页面

采用 SophiStudio 现有浅色样式，新增工作流卡片“Want · 招聘工作台”。物理入口是根目录 `want.html`，正常运行地址为本地服务 `/want.html`。页面顶部显示四岗当日摘要阅读、完整简历核查、已核验发送和待处理数量，同时提供本轮累计与历史累计切换。每项统计标注口径和资料更新时间。

页面由岗位进度、分类人员列表、详情与复核、运行日志四部分构成。列表使用分页和按需展开，不一次渲染全部历史卡片。支持岗位、日期、阅读层级、匹配分类、沟通状态、停止联系标记、复核状态及关键词组合筛选。归档岗位有独立入口。

每个人员条目呈现职业技能、项目、城市或宁波意愿的已知证据、匹配理由、待核实项、资料来源及最近复核时间。缺失信息显示“未记录”，不能用推断填补。身份尚未核实的资料保留独立条目，提示待核实，不自动合并同名人员。

## 4. 分类与二次阅读

分类使用多个独立维度，避免将资料完整度误作匹配度：

| 维度 | 分类 | 规则 |
| --- | --- | --- |
| 岗位 | 四个当前岗位、归档岗位 | 以配置与原始记录为准 |
| 阅读层级 | 推荐摘要、部分简历、完整可见简历 | 按实际保存的来源与核查记录；不能由 AI 提升级别 |
| 匹配情况 | 未评估、匹配证据充分、需要核实、当前岗位证据不足 | 依据职业事实，附理由、引用片段和缺项；属于初步沟通建议 |
| 沟通状态 | 未联系、待发送、已核验发送、结果待核验、有回复、停止联系 | 依据操作及对话证据；回复来源范围单独标注 |
| 复核状态 | 未复核、已复核、资料更新后待复核 | 与首次阅读及发送状态独立 |

已有职业证据先按确定字段建立分类索引。尚未经过本次模型评估的匹配分类保留“未评估”，不能把自动填充标签当成新增实质阅读。人工分类优先保留；模型提出的新分类以建议和差异形式显示，人工可接受或修改。

点击“二次阅读”打开已保存的资料、原来源链接、各次评估与复核记录，支持新增复核笔记和待核实项。只有摘要的历史人员显示“仅保存推荐摘要”；不能将摘要扩写成完整简历。必要时通过可用浏览器重新打开来源核验。

打开本地历史资料不增加当日新的不同人员阅读数；追加复核记录有独立时间。原 `reviewedAt`、`detailedReviewedAt`、`sentAt` 不因复核被改写。现场新获取资料与本地重读分别记录。

## 5. 消息高亮与导出

真实成功发送的消息正文采用浅绿色底、清晰边框及“已发送·已核验”文字，同时显示实际发送时间、岗位和核验依据。颜色不是唯一识别方式。待发送草稿、发送结果不明和主动来信有不同文字标签，不能用成功高亮。

同一人员的多次消息按时间排列；授权邀约正文与实际发送记录分别保存。平台界面显示的信息与模型生成内容分别标注。聊天列表摘要不得展示成完整对话，人工已发送的消息如无法确认正文或归属则保留未知状态。

支持导出全部资料、当前筛选结果或已选人员：

- Excel：分类清单、职业证据与待核实项、复核历史、消息记录、运行汇总分别成表；已核验发送正文有对应底色和状态文字。
- HTML：可独立打开的阅读报告，包含筛选条件、生成时间、分类、复核与高亮消息；所有文字安全转义。
- CSV：用于数据交换，包含状态与正文列；因格式不支持颜色，保留明确的“已核验发送”字段。

这些按需导出写为独立文件，不覆盖人工维护的原 Excel。原 `人员沟通.xlsx` 与 `renyuan.html` 的兼容同步继续保留，由后台按批次或任务结束串行执行，遵守原历史列保护和备份机制。每次导出记录数据版本；导出失败不回滚已成功发送的记录，可单独重试导出。

## 6. 后台与数据流

新增独立本地服务，只监听 `127.0.0.1`，默认端口 8770，可配置；端口占用时报告冲突，不终止其他程序。服务可通过 SophiStudio 的本地启动流程安装为 macOS 登录后台。关闭网页不终止已持久化任务；关闭 Mac 或网络中断会暂停相应步骤，恢复后从状态续接。

数据流：已采集职业资料 → 身份与联系历史检查 → 批量模型评估 → 样本比较 → 完整简历现场核查 → 固定话术发送队列 → 发送结果核验 → 持久记录 → 批次导出。

职责分离：

| 组件 | 职责 |
| --- | --- |
| want.html 与页面脚本 | 查询、筛选、详情、复核、任务控制、下载结果 |
| 数据存储模块 | 统一写入锁、版本校验、原子保存、事件历史、兼容导出读取 |
| 评估队列 | 分批请求、缓存、错误重试、记录 Codex 或 API 实际用量与阶段耗时 |
| 浏览器执行适配器 | 使用正常可见页面内容完成采集和发送，提供真实连接与登录状态 |
| 导出模块 | 串行快照导出；保护原 Excel 历史与人工修改 |

保留原始招聘记录字段。新增的模型结果、人工分类、复核历史、任务阶段与导出状态使用独立状态文件，按原始记录 ID 关联。高可信平台 ID 可用于跨记录关联；旧复合键只作辅助线索。未核实身份不自动归并。

所有修改招聘原始 JSON 的入口（含旧更新脚本）必须遵循同一写入协议：互斥锁、读取最新版本、核对前置状态、原子替换。后台只有一个发送消费者，避免并发重复发送。并行仅用于相互独立的模型评估，Codex 初始并发 1、每批最多 20 份，验证后最多提升为 2；遇到限流自动退避。模型并发与浏览器操作互不混淆。

## 7. Codex 优先的模型接入

2026-09-27 用户进一步询问如何使用现有 Codex 算力。补充的优先方案是：`want.html → 本地后台队列 → Codex CLI/SDK → 结构化评估结果 → 分类、复核、高亮与导出`。OpenAI Responses API 保留为用户主动配置的可选提供方，不作为使用网页或 Codex 评估的前提。

本机已只读核验：`codex-cli 0.139.0`，`codex login status` 返回 `Logged in using ChatGPT`。当前已安装版本的帮助中有 `exec`、`--json`、`--output-schema` 和只读沙盒参数。尚未运行真实评估批次，因此认证状态不等同于已完成模型联调或已有足够额度。

### Codex 执行方式

首版由本机同一用户的后台进程调用 `codex exec`；后续若需要更丰富的流式事件和会话恢复，可在相同适配器接口后采用官方 Codex SDK。Codex 自行复用已保存的登录，应用不读取、复制或转发账号令牌，也不直接访问未公开的 ChatGPT 接口。无需控制 Mac ChatGPT 窗口。

每个批次生成最小化输入和 JSON Schema。工作进程使用固定命令与参数数组，将资料通过文件或标准输入传入，禁止把候选人文本拼接成可执行 shell 命令。评估使用只读权限与限定工具的工作配置，不能直接修改招聘台账或调用 BOSS 发送工具；后台验证返回结果后保存。首次联调验证权限配置、认证、完整输出与可恢复性。

输出字段为输入记录 ID、匹配分类、职业依据、待核实项及建议复核重点。模型无权改变岗位职责、授权话术、发送结果或停止联系状态。记录任务 ID、Codex 会话 ID、事件、退出状态、输出文件及可获得的用量；输出与输入版本不符时不提交结果。进程中断后先检查批次状态与已有输出，可恢复的会话使用明确 ID 恢复，不能用全局“最近会话”接错任务。

使用 ChatGPT 登录的 Codex 工作消耗该账户可用的 Codex 额度，并受相应限额和账号权限约束；不将其描述为免费或无限算力。额度耗尽时保留队列并显示等待恢复，不自动切换到付费 API。后台可关闭网页继续处理，但 Mac 需保持运行并联网，休眠期间不能承诺执行。

### 共同的数据规则与可选 API

缓存键包含职业资料内容、岗位职责版本、知识库来源版本、提供方、实际模型标识和评估提示版本。任一变化使相关结果失效；人工笔记和修正不被旧模型结果覆盖。模型选择沿用可用配置，不擅自升级高成本模式。

仅提供评估所需职业资料，以内部记录 ID 替代姓名等识别字段；不将照片、年龄、性别、民族、婚育等用于匹配。自由文本资料视为数据，不能执行其中的指令。输出需要严格校验，出现未知 ID、缺失记录或错误结构时该批次不能进入自动联系队列。

用户主动启用 API 提供方时，服务端通过 OpenAI Responses API 请求结构化输出。异步请求保存响应 ID，恢复时先查询原请求，避免重复提交。API Key 仅由后台读取，不写入 HTML、浏览器存储、日志或 Git；页面只显示连接状态。API 与 ChatGPT 订阅单独计费，未经用户选择不作为自动回退。

没有可用 Codex 登录且没有已配置 API 时，仍允许浏览、人工分类、复核和导出，模型评估显示具体阻碍，不使用演示结果充当真实分析。

ChatGPT macOS 的 Work with Apps 是聊天中读取、编辑兼容应用内容的功能；它本身不是供 want.html 调用的公开本地 HTTP 模型服务。这里使用的是官方 Codex 程序化入口及其自身管理的登录，补充了上一版设计遗漏的接入方式。

## 8. 浏览器执行能力与发送保障

Codex 评估进程或 OpenAI API 本身均不自动获得可控制的 Edge 登录会话。首先验证能否建立独立、正常登录、支持后台操作的浏览器执行通道；不得为后台任务抢占用户正在使用的窗口。不复制私人会话 Cookie，不使用隐藏平台接口替代正常页面操作，不自动解答验证。用户完成登录或安全验证后，执行器重新检查实际页面。

浏览器适配器未连接时，页面显示具体阻碍，任务可以完成资料评估和队列准备，但“实际发送”保持未完成。当前系统必须经过真实后台能力验证才能启用自动发送，不能以静态按钮或模型调用成功替代此验证。

发送前需要：岗位仍开放、最新职责已核验、话术已确认、已完成样本比较、完整可见简历已核查、身份与跨岗跨日历史检查通过、没有停止联系标记、当日发送目标未达到。发送对象和精确正文先持久化；实际消息出现或界面确认后才能记为已发送。

已联系未回复者不重复发送相同邀约。对于发送中断或结果不明的对象，恢复时先检查对话，不盲目重试。每天发送数按 `sentAt` 转换为 Asia/Shanghai 的日期统计，复核或重新运行不重置额度。达到现有 20 人目标即停止该岗新增发送，除非用户明确修改目标。

登录失效、安全验证、付费开聊、次数用尽、岗位关闭时停止受影响步骤，保留进度。新二次回复只作为草稿，现有授权只涵盖已确认的四条邀约。

## 9. 状态、异常与通知

任务状态为排队、运行、等待 Codex 登录或 API 配置、等待额度恢复、等待浏览器、等待人工登录或验证、待核验结果、已完成、部分完成、失败、已暂停。模型评估、浏览器发送、报表导出分别展示进度和错误。用户可以暂停后续动作，已核验成功的发送不能被取消或回退。

正常读取不触发发送。写入接口校验本机来源和请求令牌；不开放跨域通配访问。页面只通过受控接口读取相关资料，不能任意访问项目文件。

后台异常、需要用户动作、任务完成时显示有意义的通知；重复未变化的阻碍不反复通知。既有定时任务与新服务共用互斥和当日额度，避免同一时间双重执行。首版接入后，只有确认新执行器接管成功才调整既有调度；不会同时启用两个独立发信循环。

## 10. 验收

1. SophiStudio 工作流入口可访问 want.html，遵循既有样式与导航方式，现有模块不受影响。
2. 所有历史阅读记录可检索；原始条目数与来源对得上，归档 3D 记录可见，没有误合并同名人员。
3. 二次阅读可追加并保存复核历史，首次阅读与发送时间不变；本地重读不会增加新人员阅读额度。
4. 草稿、结果不明、已核验发送在网页和 Excel/HTML 导出中可明确区分；高亮正文与记录原文一致。
5. 当前筛选导出与页面条件一致，中文正常，CSV 公式内容作安全文本处理，原 Excel 历史与人工列不被改写。
6. 无 API Key 但 Codex 登录有效时，可以选择 Codex 评估；无可用模型连接时记录管理仍可使用。以一个有限真实批次验证 Codex 完整输出、缓存、权限与用量，再运行批量任务；API 可选且不自动回退。
7. 同一任务重复触发、进程重启和同时操作旧脚本不丢失记录、不重复发送。重点覆盖跨上海日期、身份未核实、停止联系与发送结果不明的情形。
8. 凭据、登录、验证或后台浏览器未就绪时显示真实阻碍；不得将模型完成显示为招聘发送完成。
9. 发送状态即时保存，全量报表不在每次发送后生成；记录采集、评估、发送、导出耗时，以同规模资料对比优化效果。
10. 后台发送功能需实际连接和正常页面操作验证；不具备条件时按未验收交付说明，不能宣称四岗无人值守运行已完成。

## 11. 交付范围与顺序

先实现记录管理与可导出的 want.html、SophiStudio 入口、统一状态保存和后台评估队列；随后验证 Codex 模型调用与独立浏览器能力，接入发送队列及原有导出。所有功能属于同一设计，依赖未满足的部分明确显示阻碍。

本设计不重写其他 SophiStudio 模块，不引入多人云端账号体系，不修改招聘岗位薪资或职责，不做自动录用、拒绝或未经授权的二次回复。
