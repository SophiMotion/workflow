# SophiStudio PRD/SOW 项目驾驶舱设计规范

日期：2026-09-02  
状态：待书面审核  
目标文件：`prd/prd.html`

## 1. 背景与目标

SophiStudio 需要一个面向驾驶模拟器和线控底盘项目的统一项目管理入口。该入口不分别复刻传统 PRD 与 SOW，而是吸收两类文档的核心约束，将需求定义、实施计划、资源投入、BOM、预算、验收和风险变更整合为一个可持续推进的项目工作台。

设计参考内部文件 `SophiCar/sophicarbp/v4-0830chatgpt.md` 中的产品结构、项目闸门、证据纪律和交付规范，并采用“飞书式甘特图 + 项目仪表盘”的主要交互形式。

首版必须满足：

- 通过 `file://` 直接打开使用，不依赖 npm、服务器或网络资源。
- 在同一个页面中管理多个项目。
- 支持驾驶模拟器和线控底盘两类项目模板。
- 项目数据可编辑、自动本地保存，并可通过 JSON 导入导出。
- 管理需求、人员、进度、BOM、成本、预算、验收和风险。
- 集成到 SophiStudio 根工作流，整张卡片在当前标签页打开。

## 2. 产品定位

页面名称为“PRD / SOW 项目驾驶舱”，定位为 SophiStudio 工程项目从需求到验收的单一事实入口。

PRD 的信息用于回答：为什么做、做什么、关键指标和系统边界是什么。  
SOW 的信息用于回答：谁来做、何时完成、花费多少、交付什么以及如何验收。  
项目驾驶舱将二者合并为结构化数据，并从这些数据自动生成进度、成本、风险和验收视图。

## 3. 用户与使用场景

主要用户包括项目负责人、结构工程师、嵌入式硬件工程师、嵌入式软件工程师、算法工程师、采购和交付负责人。

典型使用流程：

1. 从左上角项目选择器切换已有项目，或新建项目。
2. 选择“驾驶模拟器”或“线控底盘”模板。
3. 填写项目范围、关键参数、客户与负责人，补齐项目闸门要求。
4. 将工作拆分到阶段、专业域、任务、人员和时间计划。
5. 持续更新甘特进度、BOM 实际成本、风险与变更。
6. 在里程碑处记录交付物、验收证据和客户确认。
7. 导出 JSON 进行备份或成员间传递，并打印项目报告。

- JSON 导入、导出和打印。

### 4.2 左侧导航

1. 项目总览
2. 需求参数
3. 甘特计划
4. 团队资源
5. BOM 与预算
6. 交付验收
7. 风险与变更

### 4.3 项目总览

仪表盘首屏展示：

- 预算使用率和预测结余。
- 剩余工期与工期偏差。
- 开放风险数量。

- 成本分类和团队负荷摘要。

## 5. 核心数据模型

### 5.1 项目

字段包括项目 ID、名称、客户、项目类型、负责人、优先级、状态、当前阶段、计划起止时间、实际起止时间、项目说明、预算和更新时间。

### 5.2 需求参数

需求按结构、嵌入式硬件、嵌入式软件、算法四个专业域分类。每条需求包含：

- 编号与标题。
- 要求描述、目标值和单位。
- 优先级。
- 负责人。
- 技术成熟度：已实现、在研、规划。
- 状态：待确认、已确认、进行中、已完成、已阻塞。
- 验收方法和关联验收项。
- 证据等级与备注。

驾驶模拟器模板预置座舱与操纵、视景与对象模型、控制与运动、实验与数据、交付服务等分类。线控底盘模板预置机械与动力、转向/驱动/制动线控、通信与数据、安全、载荷与扩展接口等分类。

### 5.3 任务与甘特计划

任务包含阶段、父任务、负责人、计划起止日期、实际起止日期、完成度、依赖任务、状态和备注。时间轴由任务日期动态计算，不依赖第三方甘特图库。

标准阶段为：

`立项 → 需求冻结 → 设计评审 → 采购制造 → 系统集成 → 测试验证 → FAT/SAT 验收`

甘特图左侧为任务表，右侧为时间轴。阶段可折叠；已完成任务显示绿色，当前任务显示蓝色，存在延期显示红色，未开始显示灰色。首版依赖关系以字段和关联提示表达，不绘制复杂连线。

### 5.4 团队资源

成员记录姓名、标准角色、专业域、职责、预计工时、实际工时和当前状态。标准角色包括项目负责人、系统/结构、嵌入式硬件、嵌入式软件、算法、采购制造、测试与交付等，并允许用户自定义。

### 5.5 BOM、成本与预算

BOM 项包含物料编码、名称、规格、分类、数量、单位、单价、预算成本、实际成本、供应商、采购状态和备注。

预算分类包括物料、研发工时、加工、采购、差旅、服务和风险预留。系统计算：

- BOM 预算总额与实际总额。
- 项目预算使用率。
- 分类成本分布。
- 预测结余或超支。

### 5.6 交付与验收

验收项包含里程碑、交付物、指标、验收方法、责任人、计划日期、实际日期、证据说明、证据链接/路径、状态和客户确认。未定义验收方法或证据时显示警告。

### 5.7 风险与变更

风险记录类别、描述、概率、影响、等级、责任人、应对措施、截止日期和状态。变更记录描述、原因、范围影响、时间影响、预算影响、申请人、审批状态和决策记录。

## 6. 项目闸门与证据规则

每个阶段提供检查项，但首版采用提示而非强制锁定，以允许团队按实际情况推进。

立项和关键阶段检查：

- 是否有清晰任务与客户。
- 是否指定项目 DRI。
- 是否明确预算和验收标准。
- 是否界定知识产权、数据和安全责任。
- 是否识别可复用模块。

沿用参考资料中的证据等级：F1（已确认事实）、F2（团队记录）、P（计划/线索）、H（假设）、D（历史信息）、C（冲突待核实）。未知值不得臆造，统一标记“待确认”。

## 7. 交互设计

### 7.1 项目切换与创建

左上角项目选择器显示当前项目。选择“新建项目”后打开对话框，填写名称、客户、项目类型、负责人、日期和预算。创建完成后自动生成相应模板数据，并切换到新项目。

### 7.2 编辑模式

列表和表格提供新增、编辑、删除操作。较短字段支持表格内编辑，复杂记录使用模态框。所有变更触发派生指标重新计算和自动保存。

### 7.3 空状态与确认

- 没有项目时显示新建引导。
- 没有数据的模块显示模板说明和新增入口。
- 删除项目、任务、BOM 和验收记录前二次确认。
- 预算超支、任务延期、高风险、缺少验收证据时展示明确警告。

## 8. 视觉规范

采用 Google 风格色系与浅灰背景：

- 蓝色 `#1a73e8`：需求、研究、计划和主操作。
- 绿色 `#34a853`：工程执行、通过和完成状态。
- 黄色 `#fbbc04`：待确认、预算提醒和关注项。
- 红色 `#ea4335`：风险、延期、阻塞和超支。
- 页面背景 `#f8f9fa`，卡片背景为白色，边框使用中性浅灰。

布局为顶部栏、固定左侧导航和可滚动主内容区。桌面端优先，同时在较窄屏幕下将侧栏折叠为横向导航或菜单。

## 9. 本地运行与数据持久化

`prd/prd.html` 采用单页静态实现，CSS 和 JavaScript 内嵌或使用同目录静态资源，不调用网络接口。直接打开文件即可运行。

项目集合使用浏览器本地存储自动保存。鉴于 `file://` 本地存储与浏览器环境绑定，JSON 导出是正式备份和团队传递方式；JSON 导入会校验基本版本和数据结构后恢复项目。页面同时支持浏览器打印，输出适合打印的项目摘要。

首版不宣称多人实时协同。团队协作通过导出、传递和导入项目 JSON 完成，未来可在保持数据模型兼容的基础上接入服务端或飞书数据源。

## 11. 首版范围外

- 多人实时编辑与账号权限。
- 服务端数据库和云同步。
- 与飞书、ERP、PLM 或采购系统的直接 API 集成。
- 甘特任务拖拽调整日期与复杂依赖连线。
- 文件附件上传；首版仅记录证据名称和本地/网络路径。
- 自动生成正式合同或具有法律效力的 SOW。
